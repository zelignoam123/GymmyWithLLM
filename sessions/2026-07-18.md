## What broke and how we fixed it

| Error | Root cause | Fix |
|---|---|---|
| `ModuleNotFoundError: No module named '_tkinter'` | Homebrew `python@3.11` doesn't bundle Tk; need `python-tk@3.11` separately | Added `arch -x86_64 brew install python-tk@3.11` to `setup.sh` before venv creation |
| `pypot.vrep.io.VrepIOErrors: No value` | CoppeliaSim scene not loaded — pypot tried to set joint positions on non-existent joints | (a) Auto-download `poppy_torso.ttt` in `setup.sh`; (b) pass `scene=_SCENE_PATH` to `PoppyTorso()` so pypot loads it explicitly |
| CoppeliaSim 4.10 / 4.9 / 4.7 — port 19997 missing | Legacy remote API dropped from builds ≥4.5 | Pinned to **CoppeliaSim Edu V4.1.0 macOS Intel** (last version with legacy API) |
| `"coppeliaSim" cannot be opened` Gatekeeper block | Older builds not notarized | `xattr -dr com.apple.quarantine "/Applications/coppeliaSim-4.1.app"` |
| `OpenCV: not authorized to capture video (status 0)` | macOS camera permission not granted to terminal app | `tccutil reset Camera com.googlecode.iterm2` → fully quit/reopen iTerm → run camera one-liner to trigger dialog |
| `Ignoring empty camera frame` | `cv2.VideoCapture(0)` opened from background thread — AVFoundation on macOS silently returns empty frames | Moved `VideoCapture` open to main thread in `main.py`, stored in `s.cap`, shared via `Settings` |
| `cv2.error: Unknown C++ exception` in `cv2.imshow` | `imshow` cannot create an NSWindow from a background thread on macOS | Disabled `cv2.imshow` in `MP.py`; added live thumbnail in Tkinter window instead (runs on main thread) |
| `arch: invalid option -- 'x'` in `setup.sh` | Running `setup.sh` inside a Linux container (Claude's shell), not on the Mac | Run `./setup.sh` and `./run.sh` from a macOS Terminal / iTerm2 / VS Code terminal, not the Claude shell |
